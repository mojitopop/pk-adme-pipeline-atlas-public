## S1 · Acquire — PDF · JSON · HTML  →  raw text + compound identity

> Scrape 6 regulator label sources into raw pk_text + resolve per-compound CID/UNII identity (tiered).

**Repo:** `db_crossref`  ·  **Source dir:** `db_crossref/`  

**God node:** `build_compound_identity.py` — It is the terminal node of the identity chain and produces raw_llm_txt.compound_identity — the one-row-per-compound table (plus mono_substance_identity / combination_products views) that every downstream stage joins on via row_id and unii. Its explode_row() encodes the stage's core honesty rules (metabolite-no-inherit, product-id-nulling, same_as_parent, is_biologic) and stamps resolver_tier/confidence/inherited_flag, making it the authoritative definition of what 'compound identity' means for the whole pipeline. The CORPUS_REFRESH_RUNBOOK.md is the companion anchor doc, but this script is the code that emits the stage's canonical output.

Stage S1 'Acquire' turns regulator drug labels from six sources into two artifacts: raw text (the pk_text column of table raw_llm_txt.txt, one row per drug-per-source) and a normalized compound-identity table (raw_llm_txt.compound_identity) carrying CID/UNII with a resolver_tier trust concept. Text acquisition splits by source family: the smpc_scraper package (run.py -> ema.py/emc.py/mhra.py) downloads EMA EPAR PDFs, UK emc HTML and UK MHRA PDFs, then extract_sections.py slices out the PK-relevant QRD sections (§5.2 pharmacokinetics, §4.5 interactions), sha256-dedups them and writes the smpc_section table in the pharmacologie DB; insert_to_corpus.py then upserts those §5.2/§4.5 sections into raw_llm_txt.txt as SmPC_* rows (stable upsert keyed on db_source+meta_source so existing row_ids and their downstream detection work survive). FDA SPL JSON, Wikipedia and HSDB rows arrive as other db_source values ('FDAlabels','wikipedia','HSDB'), and French ANSM RCP .htm rows ('RCP') are parsed for salt nomenclature by fr_parse.py/fr_merge.py with UNII backfilled by the exact-match GSRS scraper (gsrs_unii_scraper.py) and the Wikipedia-infobox harvester (wiki_rcp.py). Identity assignment is a three-hop chain driven off pk_text: compound_detect/02_detect_compounds_shard.py runs a qwen2.5 model on the cluster to detect each row's parent + active metabolites + co-actives, 03_load_compounds_to_db.py loads that back into raw_llm_txt.detected_compounds and emits roster.json, and pktext_enrichment.py resolves every compound's own identifiers into raw_llm_txt.compound_enrichment by calling metabolite_resolver.resolve() (tier 1 exact-name, tier 2 metabolite-specific NCATS/ChEMBL, tier 3 substring/synonym LIKE = fuzzy, tier 4 InChIKey/CAS structure bridge) with the parent passed in so the inherited-identity guard fires. build_compound_identity.py finally explodes that enrichment sidecar into the one-row-per-compound compound_identity table, NULLing a metabolite's own ids unless genuinely resolved (v66 no-inherit fix), demoting combination brands to compound_kind='product', and flagging same_as_parent / is_biologic. pubchem_names_ids.py is a read-only lead generator for the tier<=2 gaps and manual_overrides.csv (tier-0 authoritative) lets a human hand-fill ids the local DBs cannot resolve. Everything but the GPU detection step is local, deterministic and rebuildable; manual overrides are re-applied on every enrichment run so they survive full rebuilds.

**Reads**
- `EMA/MHRA PDF + UK emc HTML SmPCs (downloaded docs)` (file; from external regulator sources)
- `FR ANSM RCP .htm (ansm_corpus/RCP_docs)` (file; from external regulator sources)
- `FDA SPL JSON / Wikipedia / HSDB rows` (file; from external regulator sources)
- `pharmacologie.smpc_section` (db_table; from external (extract_sections.py))
- `roster.json (detected parent/metabolites/coactives)` (file; from S1 internal (03_load_compounds_to_db.py))
- `manual_overrides.csv (tier-0 authoritative id fills)` (file; from human curation)
- `local identity DBs (FDA substances, drugbank_extracted, pubchem.*, ChEMBL, NCATS analyte)` (db_table; from external reference DBs)

**Writes**
- `raw_llm_txt.txt (pk_text raw row per drug-per-source)` (db_table; to S2 PK-value extraction)
- `raw_llm_txt.compound_identity (+ mono_substance_identity, combination_products views)` (db_table; to S2 PK-value extraction / identity consumers)
- `raw_llm_txt.detected_compounds (detection sidecar) + txt_detected view` (db_table; to S1 internal -> enrichment)
- `raw_llm_txt.compound_enrichment (per-row compounds_json id sidecar)` (db_table; to S1 internal -> build_compound_identity)
- `roster.json` (file; to S1 internal (pktext_enrichment))
- `out/pubchem_lookups/*.json (identity-gap review files)` (file; to human curation)

**DB tables**

| Table | Mode | Writer |
|-------|------|--------|
| `raw_llm_txt.txt (col pk_text)` | read/write | smpc_corpus/insert_to_corpus.py (SmPC rows; other db_source rows via FDA/wiki/HSDB/RCP loaders); read by all identity scripts on row_id |

**Hand-off in:** External regulator sources (EMA EPAR PDF, UK emc HTML, UK MHRA PDF, FR ANSM .htm RCP, FDA SPL JSON, Wikipedia/HSDB) land as raw documents; SmPC sources pass through pharmacologie.smpc_section (written by extract_sections.py, keyed by source+doc_ref+section_code) before insert_to_corpus.py upserts them into raw_llm_txt.txt. S1 is the first stage, so there is no prior-stage table — the true boundary-in is the scraped document set keyed to raw_llm_txt.txt.row_id (the AUTO_INCREMENT PK, MAX+1 convention).

**Hand-off out:** Two joined artifacts on row_id: (1) raw_llm_txt.txt.pk_text = the raw PK/ADME text a row supplies; (2) raw_llm_txt.compound_identity (+ views mono_substance_identity, combination_products) = per-compound CID/UNII/role/parent_unii with resolver_tier + inherited_flag. Downstream PK-value extraction (pk_new_nu_model_vNN) builds its input CSV from raw_llm_txt.txt rows keyed by row_id/meta_source and reads pk_text; identity consumers join on row_id and on unii. FK compound_identity.row_id -> txt.row_id (ON DELETE CASCADE) is the enforced join key.

### Scripts & functions

#### `build_compound_identity.py`
God node: explode compound_enrichment sidecar into the normalized one-row-per-compound raw_llm_txt.compound_identity table + mono/combination views.

- **`explode_row`** `L117` — Yield one insert-tuple per compound in a row's compounds_json; assigns role, NULLs own ids unless identity_resolved (metabolite-no-inherit), demotes combo brand parent to compound_kind='product', computes same_as_parent, links metabolite to longest-prefix parent/co-active name.
- **`is_biologic`** `L42` — Flag vaccines/biologics/TPN/panels (regex + length>120) so they are excluded from the mono-substance view (not deleted).
- **`inchikey_skeleton`** `L47` — Derive connectivity-only skeleton (first InChIKey block) as pure string op so it survives DROP+CREATE rebuild.
- **`main`** `L188` — Read compound_enrichment ordered by row_id, tally by role/inherited/same_as_parent, and on --commit DROP+CREATE+batch-insert the table and rebuild the two views.

  ↔ _interacts with:_ `raw_llm_txt.compound_enrichment`, `raw_llm_txt.compound_identity`, `raw_llm_txt.txt (FK row_id)`, `pktext_enrichment.py (upstream writer)`

#### `pktext_enrichment.py`
Resolve every compound's own identifiers into the compound_enrichment sidecar (1:1 on row_id), applying manual_overrides.csv as tier-0 and calling metabolite_resolver with the parent for the inherited-identity guard.

- **`_load_overrides`** `L61` — Load manual_overrides.csv keyed by (parent, compound-surface-name) lower-cased; two modes (real_name to re-resolve, or direct unii+ids stamp).
- **`_norm_key`** `L57` — Lower/strip name key for override matching.

  ↔ _interacts with:_ `metabolite_resolver.py`, `manual_overrides.csv`, `compound_detect/roster.json`, `raw_llm_txt.txt`, `raw_llm_txt.compound_enrichment`

#### `metabolite_resolver.py`
Deterministic read-only tiered identifier resolver: given a compound name, return its OWN unii/chembl/cas/inchikey/cid with a resolver_tier and inherited_flag.

- **`resolve`** `L442` — Public API; run tiers in order (first hit wins) + tier-4 structure bridge, apply inherited-identity guard when a parent is supplied (flags a metabolite id that collapsed onto the parent's).
- **`normalize`** `L70` — Upper/strip registry tags + [NO STEREO] prefix, preserve locant hyphens/digits load-bearing in metabolite names.
- **`_tier1_fda_substances`** `L127` — Tier-1 exact normalized-name match against FDA substances_names giving UNII directly (trusted tier).
- **`_tier3_like`** `L286` — Tier-3 substring/synonym LIKE fuzzy match (the tier>2 = untrusted boundary).

  ↔ _interacts with:_ `pubchem.*`, `drugbank_extracted`, `FDA substances tables`, `NCATS analyte / ChEMBL`, `pktext_enrichment.py (caller)`

#### `smpc_corpus/insert_to_corpus.py`
Upsert the picked latest §5.2/§4.5 SmPC sections from pharmacologie.smpc_section into raw_llm_txt.txt as SmPC_* pk_text rows, inheriting UNII/CID/drugbank ids by name match.

- **`lookup`** `L43` — Match a drug_key or active-substance name against an id-inheritance map (skips combos containing +|;/) to inherit unii/drugbank/cid/canonical name.
- **`cut`** `L67` — Truncate label fields to target column widths.

  ↔ _interacts with:_ `pharmacologie.smpc_section`, `pharmacologie.ema_smpc/uk_emc_smpc/uk_mhra_doc`, `raw_llm_txt.txt`, `extract_sections.py (upstream)`

#### `smpc_corpus/smpc_scraper/extract_sections.py`
Turn downloaded EMA/MHRA PDFs + emc HTML into a deduplicated cross-source-linked corpus of PK/ADME QRD sections (§5.2, §4.5) -> smpc_section table + pk_ddi_corpus.jsonl.

- **`section split/dedup/linkage`** `L1` — Split emc by <summary id>, PDFs by QRD anchor-slicing (pymupdf); sha256-dedup with is_primary=1 on first occurrence; build normalized drug_key + inherited ATC across sources.

  ↔ _interacts with:_ `smpc_scraper/run.py`, `smpc_section table`, `insert_to_corpus.py (downstream)`

#### `smpc_corpus/smpc_scraper/run.py`
CLI entry point for the SmPC scrapers: refresh catalog -> download -> dedup for ema/emc/mhra sources.

- **`main`** `L34` — Dispatch to ema.run/emc.run/mhra.run per source arg (or all).

  ↔ _interacts with:_ `ema.py`, `emc.py`, `mhra.py`, `db.py`, `common.py (polite_get/RateLimiter)`

#### `compound_detect/02_detect_compounds_shard.py`
Cluster GPU step: run qwen2.5 over pk_text shards to detect per-row parent + active metabolites + co-actives (DB-free, stdlib urllib).

- **`ollama_chat`** `L44` — POST to Ollama /api/chat with format=json, temp 0, returning strict-JSON detection per row.
- **`parse_obj`** `L57` — Parse/repair the model's JSON detection output.

  ↔ _interacts with:_ `shards/*.jsonl (from 01_export_txt_splits.py)`, `detected/*.jsonl`, `03_load_compounds_to_db.py (downstream)`

#### `compound_detect/03_load_compounds_to_db.py`
Local loader: read detected_*.jsonl and write raw_llm_txt.detected_compounds sidecar + emit roster.json in pktext_enrichment --roster shape.

- **`load_detected`** `L50` — Glob + parse detected JSONL keyed on row_id, tally, and build sidecar/roster rows.

  ↔ _interacts with:_ `detected/*.jsonl`, `raw_llm_txt.detected_compounds`, `raw_llm_txt.txt (FK)`, `roster.json`, `pktext_enrichment.py`

#### `gsrs_unii_scraper.py`
Exact-match-only UNII resolver for French RCP salt drugs via FDA GSRS public API (precision over recall; salt form, not base).

- **`FR->EN salt translate + exact-match keep`** `L1` — Translate FR salt name to EN salt query, GSRS phrase-search, keep UNII only when exactly one returned substance name equals the query (normalized); ambiguous/none left blank for manual fill.

  ↔ _interacts with:_ `ansm/RCP components`, `rcp_fill_worklist CSVs`, `manual_overrides.csv (manual downstream)`

#### `wiki_rcp.py`
Harvest UNII + CID for still-unresolved French RCP components from English-Wikipedia infoboxes via the operator's wikipedia scraper.

- **`--build / --harvest`** `L1` — Build page-title guesses from FR->EN morphology (salt-stripped, flags base-of-salt), then map identifiers__UNII/PubChem_CID back to each FR component into rcp_fill_worklist.autofilled.csv + rcp_still_missing.csv.

  ↔ _interacts with:_ `../../wikipedia/ scraper`, `fr_parse.py`, `rcp_fill_worklist CSVs`

#### `fr_parse.py`
Parse French RCP salt-nomenclature parent name strings into resolvable base names (split pipe/semicolon, strip salt + hydrate qualifiers).

- **`coverage measure`** `L1` — Measure how many unresolved RCP parents resolve after salt-parsing, via metabolite_resolver.

  ↔ _interacts with:_ `metabolite_resolver.py`, `fr_merge.py`, `raw_llm_txt.txt (db_source='RCP')`

**Invariants / honesty rules**
- Metabolite-no-inherit (v66 fix): a compound's own unii/cid/chembl/cas/inchikey/drugbank columns are populated ONLY when identity_resolved is genuinely true; unresolved/bare-generic/inherited compounds keep own-ids NULL and preserve linkage via inherited_flag + parent_unii — a metabolite NEVER carries the parent's UNII.
- resolver_tier trust boundary: tier 1 (exact name) and tier 2 (metabolite-specific NCATS/ChEMBL) are trusted; tier 3 is substring/synonym LIKE (fuzzy, untrusted, e.g. the Kaftrio bortezomib/bivalirudin false-positive landmine); tier 4 is structure-bridge backfill. A tier-1 exact hit is never flagged inherited.
- Combination-brand demotion: a combo whose parent has no own unii, or whose unii is merely one component's (entresto->valsartan), becomes compound_kind='product' with all own ids NULLed and is dropped as a link-back target.
- same_as_parent honesty flag: when a metabolite/co-active's own (correct) unii coincides with its attributed or row-primary parent's unii, it is flagged (not deleted) — the parent row itself is never flagged.
- is_biologic: vaccines/biologics/parenteral-nutrition/panels are flagged and excluded from mono_substance_identity, never deleted.
- compound_identity is fully derived + reproducible: DROP+CREATE rebuildable at will; scripts are READ-ONLY on everything except their own output table; DRY-RUN is the default and --commit is required to write.
- Manual overrides survive rebuilds: manual_overrides.csv is tier-0 authoritative and re-applied on every pktext_enrichment run (edit as UTF-8, never Excel).
- Non-destructive upsert: insert_to_corpus.py keeps existing SmPC row_ids (UPDATE in place, no DELETE) so FK-cascade never wipes downstream compound_detect / metabolite-UNII / manual_overrides work keyed on row_id; stale prior rows are left untouched, not deleted.
- PubChem lead generation is strictly read-only (no DB/CSV writes) and precision-first: 0 CIDs=honest-NULL, >1=ambiguous with nothing fetched (never guess which CID).
- GSRS/Wikipedia RCP UNII resolution is exact-match-only precision-over-recall: keep a UNII only on exactly one exact name match (salts, stereoisomers, hydrates excluded); ambiguous/none left blank for manual fill.
- Naming correction: the diagram's 'txt.pk_text' is actually the pk_text COLUMN of table raw_llm_txt.txt (DB raw_llm_txt), not a table named txt.pk_text; smpc_section lives in the separate pharmacologie DB.
- FK column type discipline: detected_compounds/compound_identity FK row_id is INT UNSIGNED to match txt.row_id int(10) unsigned (a signed FK fails errno 150).
- inchikey_skeleton derived as pure string op inside the rebuild so it needs no post-rebuild ALTER+UPDATE backfill.

## S2 · Clean & excise — raw text  →  table-excised prose variants

> Excise tables from raw pk_text into aligned v1/v2/v3 variants + a row_id-joinable raw-table corpus.

**Repo:** `llm_table_parse`  ·  **Source dir:** `llm_table_parse/`  

**God node:** `build_pk_text_variants.py` — Single source of truth for table LOCATION and the three aligned label variants (v1 pk_text / v2 [TABLE:Tn] / v3 prose) plus table_map. Both qwen_excise_tables.py and materialize_pk_text_clean.py import its helpers (_norm_map, table_cells, _specific_numbers, table_footprint, numbers_in, number_conservation, is_noise_number) rather than reimplementing them, and its locate_all/build_variants define the whole stage's data model and honesty guards.

Stage S2 "Clean & excise" takes the raw per-document PK text produced upstream (raw_llm_txt.txt.pk_text, one row per document keyed by row_id) and produces three byte-aligned variants of each label plus a raw-table corpus. It runs in two writer legs. Leg 1 is the table corpus: build_table_corpus.py (extract_fda/extract_ema/extract_rcp/extract_wiki/extract_smpc_emc/extract_smpc_mhra/extract_smpc_ema) pulls every raw <table> from each source database/PDF, joins it to txt.row_id via meta_source (FDA set_id, EMA medicine#, SmPC doc_uid/emc_id, RCP cis), assigns the stable id {row_id}#t{i} through the shared _emit helper, dedups within-row numeric duplicates (_dedup_rows), and writes data/triage/table_corpus.csv; load_table_corpus_to_db.py reloads that CSV into raw_llm_txt.extracted_tables (id PK, joinable to txt by row_id). Leg 2 is the god node, build_pk_text_variants.py: for every txt row with extracted_tables it locates each table's flattened footprint inside pk_text (locate_all: manual override, exact whitespace-tolerant substring, numeric-cluster find_span_by_numbers) and emits v1 (byte copy of pk_text), v2 (each located span -> [TABLE:Tn]), v3 (each [TABLE:Tn] -> table prose only when number_conservation confirms every distinct value survives), plus table_map {Tn: extracted_tables.id} and safety_flags, into raw_llm_txt.pk_text_variants (row_id PK). FDA rows take an exact path (fda_ordered_from_cache replays extract_fda's _FDA_MASKS id-assignment walk against the cached label JSON so positions, not table text, key each id). Tables the deterministic locator cannot place are flagged "appended"; qwen_excise_tables.py drives a local qwen2.5 (Ollama, ExcisionLLM) over the whole pk_text to propose garbled-table spans, then verify_spans keeps only byte-exact substrings and reconcile_to_table_ids maps them to appended ids, emitting *_qwen_eyeball.csv for human review (apply_manual_spans.py). materialize_pk_text_clean.py finishes the last mile, resolving residual [TABLE:Tn] in v3 (inline -> restore byte-identical v1 span, appended -> drop) and writing txt.pk_text_clean non-destructively. The remaining top scripts (clean.py, fda_reader.py, wikipedia_reader.py, llm.py, groundtruth.py, triage_core.py) are the older per-table clean-to-prose-and-verify path that produces/verifies the prose bodies leg 2 later splices.

**Reads**
- `raw_llm_txt.txt (row_id PK; pk_text, db_source, meta_source, drug_name, unii)` (db_table; from S1)
- `pharmacologie_fda.fda_labels (json_data_pruned *_table masks, latest version per unii)` (db_table; from external)
- `pharmacologie.uk_emc_smpc / uk_mhra_doc / ema_smpc (SmPC source docs + doc_path PDFs/HTML)` (db_table; from external)

**Invariants / honesty rules**
- LLM = lead generator, not source of truth: qwen_excise_tables proposes spans, but verify_spans keeps only whitespace/confusable-normalized byte-exact substrings of pk_text and always returns pk_text's own slice, never qwen's copy.
- Number conservation: v3 prose may replace a table span only if it keeps every distinct number the extractor would have seen (value-aware: 034.2==34.2, 1.00==1.0); default strict (tolerance 0, no noise waiver). Failing tables keep the literal [TABLE:Tn].
- numbers_in(pk_text) subseteq numbers_in(pk_text_clean): materialize_pk_text_clean's acceptance gate asserts no real raw number is lost and 0 [TABLE:Tn] leaks before --commit.
- FDA ids are position-keyed, not text-keyed: fda_ordered_from_cache replays extract_fda's exact _FDA_MASKS walk so byte-identical duplicate tables (repeated verbatim across masks) each keep their own {row_id}#t{i}; a prior text-keyed dict orphaned ids on 5/356 rows.
- clinical_pharmacology_table slots are traversed but dropped (_FDA_DROP) to keep the id counter stable while never inserting a table whose prose has no home in pk_text.
- Ground truth comes from structured Records, never the raw blob: bare trailing digits are never footnote markers (only sup/symbol runs are), so marker digits can't pollute the value set.
- Non-destructive last mile: txt.pk_text is never mutated; pk_text_clean is an added column (revert = DROP COLUMN); pk_text_variants is DROP+CREATE idempotent, extracted_tables reload is idempotent.
- Locator precedence is manual > exact > numeric with overlap suppression; the numeric-cluster locator (find_span_by_numbers) is duplicated verbatim as a private copy in qwen_excise_tables to avoid rippling into the frozen path.
- skip-flagged non-PK tables denoise to the bracket-wrapped SKIP_PROSE_SENTINEL (single source of truth), never the retired bare word 'skipped' which is indistinguishable from real clinical prose.

## S3 · Prose — garbled tables  →  faithful prose, folded into frozen text

> Garbled PK tables -> number-conserving Sonnet/qwen prose, folded back into txt.frozen_cleaned_pk_text for the extractor.

**Repo:** `gold_extraction`  ·  **Source dir:** `gold_extraction_pipeline/`  

**God node:** `llm_table_parse/materialize_frozen_cleaned_pk_text.py` — It writes the stage terminal output, txt.frozen_cleaned_pk_text, the FINAL single extraction-ready text the downstream extractor consumes. All upstream products converge here: pk_text_variants (v1/v2 + table_map + safety_flags) plus extracted_tables.(flag, caption, prose, footnotes), resolved per-placeholder into clean prose. It reuses the core resolver (recover_inline_spans, table_footprint) and the SKIP_PROSE_SENTINEL + placeholder_guard invariants, embodying the whole fold-prose-back-into-frozen-cleaned-text contract.

Stage S3 turns garbled/flattened PK tables into faithful English prose and folds that prose back into the label text so the downstream extractor reads clean, number-conserving input instead of numeric soup. Prose is authored two ways, both reusing one strict table-to-prose rule set (sonnet_rescue.system_for() in llm_table_parse): sonnet_rescue.py re-summarizes the tables a human escalated from the triage app (calling claude-sonnet-4-6, clustering byte-identical duplicates so one call fills all twins), and prose_tables_sonnet.py (gold_extraction_pipeline) runs the same prompt on a WHOLE corpus row for transplant test drugs not in the triage app. Every Sonnet result is scored by the same number gate the triage uses (groundtruth.numbers_in / sonnet_rescue.score): every extracted mock value must reappear or the row FAILs. add_prose_column.py is the single authoritative writer that folds triage finals + Sonnet CSVs into raw_llm_txt.extracted_tables.prose (+ prose_source), joining by id-or-legacy_id and passing text through arrow_normalize.normalize_arrows. materialize_pk_text_clean.py then materializes the number-conserving intermediate txt.pk_text_clean from the three aligned variants built upstream by build_pk_text_variants.py (v1 pk_text, v2 pk_text_no_tables with [TABLE:Tn], v3 pk_text_clean), resolving every residual [TABLE:Tn] where inline placeholders restore the byte-identical original v1 span via recover_inline_spans(), appended ones are dropped, and flag='skip' tables collapse to SKIP_PROSE_SENTINEL, asserting the raw pk_text numbers are a subset of pk_text_clean numbers with zero [TABLE:] leaks. materialize_frozen_cleaned_pk_text.py produces the FINAL extraction-ready txt.frozen_cleaned_pk_text by assembling v2 + extracted_tables.(caption, prose, footnotes) per placeholder (skip becomes [TABLE OMITTED - NOT RELEVANT], prose becomes caption/prose/footnote, no-prose inline restores the raw span, appended is dropped), diverging from pk_text_clean by actually removing garbled table text wherever a reviewed/prosed replacement exists. qwen_excise_tables.py is the local-LLM sibling that helps the earlier locator place appended-tier tables the deterministic locator missed under the same LLM-proposes/deterministic-verifies rule, and placeholder_guard.py is the defense-in-depth detector both materializers run before writing model input.

**Invariants / honesty rules**
- Numbers conserved: materialize_pk_text_clean asserts the raw pk_text numbers are a subset of pk_text_clean numbers - every REAL raw number survives (STRICT tolerance 0 default; small unit-free integers waivable only under --ignore-noise via is_noise_number).
- Sonnet/qwen = lead generator, deterministic code = source of truth: prose PASSes only if the number gate (sonnet_rescue.score / groundtruth) reproduces every extracted mock value; qwen spans must byte-exact-verify against pk_text before use, never guessed.
- No [TABLE:Tn] ever leaks into final model input - both materializers run placeholder_guard.scan_text and print a '0 [TABLE:] leaks' acceptance gate before --commit.
- Inline residual tables restore the byte-identical original v1 span (recover_inline_spans via v1/v2 alignment); appended tables are dropped (raw table was never inline in pk_text).
- Skip sentinel single source of truth: apply_review_skips.SKIP_PROSE_SENTINEL='[TABLE OMITTED - NOT RELEVANT]' (bracket-wrapped, replacing ambiguous bare 'skipped'); its dropped numbers are intentional (skip_lost), excluded from num-loss.
- Non-destructive + reversible: materializers only ADD columns (pk_text_clean / frozen_cleaned_pk_text); txt.pk_text never mutated (revert = DROP COLUMN). Dry-run by default; --commit required to write.
- Single authoritative prose writer: extracted_tables.prose written ONLY by add_prose_column.py (triage 'done' wins over Sonnet); it does not re-locate or re-choose prose.
- Train==inference prompt import: prose_tables_sonnet.py reuses sonnet_rescue.system_for verbatim so the whole-row and triage-escalate arms transform tables under identical rules.
- frozen_cleaned_pk_text intentionally differs from pk_text_clean: it REMOVES garbled table text wherever a reviewed/prosed replacement exists (caption/prose/footnote), whereas pk_text_clean keeps the number-conserving raw fallback.
- All assembled text is arrow/glyph normalized (normalize_arrows) on both sides so a glyph-to-char shift never reads as a false number loss; AMBIGUOUS_PUA_CODES are never auto-converted and are reported.

**Invariants / honesty rules**
- Pass order is fixed: Pass 0+1 detect_and_filter -> Pass 1 route_and_run_pass1 -> Pass 2 (baseline nuextract_per_compound + router nuextract_per_category) -> Pass 3 grounding_check_counts -> Pass 4 llm_verify_values -> Pass 4b correct_low_score_values, then union+materialize (verified in run_per_category_full L710).
- No hard-stripping: the full raw label text flows through Pass 0; qwen2.5:32b returns ADME-categorised verbatim, and both arms ground/verify against the full _original_pk_text.
- The baseline nuextract_per_compound (extract_json_ADME) front-end is held CONSTANT across the full and baseline arms; only the enhanced router/verify machinery differs (ablation control).
- ratio_to_parent[] is STATED-only. No code anywhere in the pipeline derives `ratio` — it may never be computed by dividing two independently-extracted AUC/Cmax PKVs (_RatioToParent docstring, schema.py L499; SCHEMA_v4_field_reference §5.3 'I-forbidden').
- ratio_to_parent is metabolite-only and DOUBLE-gated: cfg.capture_ratio_to_parent (default FALSE) AND _is_metabolite_type(compound_type). The slot is only ever added to a metabolite-shaped template, never a parent one. _coerce_ratio_to_parent never INJECTS the key when absent, so the flag-OFF path stays byte-identical.
- excreted_as is UNGATED — it ships inside prompts._ELIM_PKV (L632) and has no cfg flag. Its label is VALUE-anchored, not clause-level: one mass-balance sentence yields a different species per number it carries (25.3% of gold PKVs share clause text with a differently-labelled sibling). `unchanged` must never be inferred from the ABSENCE of a species statement; a bare number defaults to `total`.
- excreted_as is in pass3._GR_SKIP (L102) because it is a controlled enum usually DERIVED by recover_excreted_as_from_source, not quoted — but excretion_note is deliberately NOT skipped and stays grounded as verbatim text.
- Every new field must be wired end-to-end (pass0 retention -> pass2 + pass2_router templates -> schema -> pass3 grounding -> pass4 verify -> pass4b correction-retry template -> export) or its value is silently dropped. Pass 4b _correct_one_field uses its OWN _FIELD_TEMPLATE_BASE (L2138), separate from prompts.py.
- A template slot with no worked few-shot demo is not reliably emitted by NuExtract (the v77 lesson) — hence both apply_excretion_species_example and _correction_retry_example_excretion. The latter is deliberately NAME-FREE because the EXAMPLE_DRUG few-shot leak into live verbatim_source (MASTER_TODO row 2501) is still open.
- verbatim_source / source_snippet are checked by _GR_VERBATIM (L116) as an exact case-sensitive source substring, so Pass 0/2 must not translate, paraphrase, or correct evidence text.
- slice_only_extract.py must never import passes.pass4 or call run_per_category_full — AST-proven in V108_CHANGES.md. Its dropped-verbatim sidecar is audit-only and never re-enters verbatim_slice, prompts, parsed JSON or any export. Malformed resume JSONL and duplicate resume keys abort loudly rather than silently skipping.
- Table-sharding routes through run_baseline_arm (L915), which never runs Pass 4 at all — a known, separately-tracked limitation, not a bug in this stage.
- An Ollama connection failure hard-halts the whole run (OllamaUnavailable, main.py L83) BEFORE the current row is written, so re-running the same command resumes from it; the lossless *.extractions.jsonl sidecar (not the truncatable xlsx) is the resume source of truth.
- Per-value context/context_note/context_signature_key are materialized deterministically AFTER the per-category Pass 4 loop; the combination-product flag stays compound-level only and never enters the signature key.
- Eval39-slice granular load is UNION-ONLY/additive and BINDING: append, never replace (a replacing load already destroyed a real ddi_role regression's evidence). The append is read-modify-write at ATOM granularity — one verbatim_slice already carries a joined multi-span separator (newline, ellipsis, newline; ~9 pieces), so comparing whole slices never matches and every re-run would look 100% new and duplicate the column. Phase-1 additive-load regression gate: a dry run must report '0 of 1421 matched' changed.
- Eval39-slice counting + resume: count DISTINCT row_id over *.slice_only.jsonl ONLY (globbing *.jsonl also catches the separate *.prose_slice.jsonl stream, giving impossible totals); use plain WRITE_MODE=resume, never SKIP_EXISTING_ROWS — its seen_keys is built from every record including row_error rows, so it can permanently hide errors.
- Eval39-slice cfg.num_ctx auto-calibrates up to 32000 via calibrate_num_ctx() off the corpus's real max text length (not a fixed floor) — this silently CPU-spilled qwen2.5:14b+NuExtract on a 23GB RTX6000 (looked like a hang, was not). filter_rows_by_text_tokens() SILENTLY DROPS over-cap rows (aggregate counts only, no row_id identity preserved); exclude_row=1 is a real wired filter (filter_excluded_rows + COALESCE(exclude_row,0)<>1), not a dead column.

**Invariants / honesty rules**
- Locator spans are mechanically grounded: locate_span only ever returns text SLICED from the real source, so confidence=='high' rows are auto-applied with no review gate. Only 'high' is ever applied — 'medium' does not occur in practice across any of the 3 corpora.
- Generative repair is gated, not trusted: run_verbatim_repair.strict_source_contains (L89) rejects any qwen reply that is not an exact substring of the source, and the reply must carry the 'VERBATIM_REPLACEMENT:' sentinel. Ungrounded output becomes fail_not_grounded, never an accepted repair.
- FLAG-NOT-SILENT-FIX (owner instruction 2026-07-17): when a grounding sentence names >=2 candidates for the same field, the field stays null AND the item is stamped _ambiguous_<field> plus a CSV row. Silent abstention is indistinguishable from 'no signal' and is banned.
- Fill-only, never overwrite: every deterministic classifier/recovery/fed_fasted pass writes ONLY into a currently-null field, and reads ONLY that PKV item's own grounding text — never surrounding paragraphs, never the whole document.
- Every --apply writes a .bak_<stamp> per touched file plus a JSON diff log; dry-run is the default on every mutating script in the stage.
- The reverse round trip is never a blind copy: reapply_verbatim_repairs uses the merge diff logs and skips+flags any item whose live value matches neither old nor new, because the corpus has been independently edited since (dedup, restructures, manual fills).
- pkv_shape_sanity_check is explicitly NOT a blanket allow-list — schema.py's _PKV permits every field on every family (extra=allow) and several legitimate fields are populated only by downstream derive_* functions, so 'not in the prompts.py template' is not evidence of a bug. Only cited rules drop; everything else is left alone.
- A field present with a null/empty value on the wrong family is the known Sonnet placeholder-stamping pattern, not a violation (_has_real_value L188).
- Read-only means no --apply: unit_sanity_audit_20260721.py deliberately ships without one — threshold and regex are the owner's call.
- DB access is strictly SELECT-only against raw_llm_txt.txt.frozen_cleaned_pk_text; missing row_ids are reported, never raised.
- Track A / Track B separation: priority18 is the ONLY corpus in both tracks, so only priority18 fixes reach the live training JSONL. oldCorpus/WideNet repairs are real but dormant (measured 0/4664 and 0/4745 key matches against Track A).
- pk_events are derived in-corpus for all 3 corpora via the real event_compiler.build_event_view, but are explicitly FILTERED OUT of the training path — convert_sonnet_distillation_to_nuextract.map_compound now counts the drop in OUT_OF_SCOPE rather than dropping silently.
- Slice cells keep an item ONLY on exact grounding-substring match against THAT slice; items with no grounding text, or grounded elsewhere, are residualized with a reason, never guessed into the slice.
- A slice target that projects to identity fields only is skipped — an empty completion would train 'emit nothing' on a real input.
- Scenario slice kinds are counted-and-skipped, not silently dropped: pass2_router has no offline prompt builder (build_category_prompt/project_category_target do not exist anywhere yet).
- unit_sanity_audit VENDORS evaluate.py's _norm_unit byte-comparably rather than importing across trees, because a cross-tree import into a version-numbered dir breaks the moment the active version bumps to v109.

**Invariants / honesty rules**
- Per-arm VAL gains do NOT reliably transfer to the merged gold39 number -- confirmed 4 times on COARSE checkpoint selection (v3-recall-thinking-off 2026-08-03: dist/elim val UP but gold39 DOWN; v2-granular 2026-08-05: dist+elim beat the winner on val yet the merged recall dropped 0.744->0.711, F1 0.811 < 0.834). The QUALIFIED exception: the SAME v3 base with a DENSE (every-25) checkpoint hunt (2026-08-04) DID carry per-arm gains to the merged number (F1 0.859 > 0.834) -- so the lesson is 'coarse selection does not transfer', not 'selection never transfers'. Never crown a per-arm val win as a merged-recipe win without a gold39 re-score, and prefer dense over coarse selection when re-picking.
- In-loop F1, offline-swept F1 and the post-hoc gold report share ONE metric definition. Both make_generative_eval_callback (train_lora.py) and eval_checkpoints.py import score_all_params_v2.score_pairs directly rather than reimplementing scoring, so all three numbers are computed by the identical function -- they are not allowed to drift.
- Vision tower must stay frozen -- twice, every profile. discover_lora_targets (train_lora.py L638-640) SystemExits if the regex catches any visual.* module, and audit_trainable_modules (L656-659) re-checks named_parameters after get_peft_model and refuses if any visual tensor requires grad. This guard applies identically to nuextract2_qwen25vl and nuextract3_qwen3 profiles; never disable it.
- LoRA targets are DISCOVERED from the live model, never assumed. A regex matching zero modules is a hard SystemExit that prints real projection names (L634) rather than silently training nothing. scripts/probe_lora_targets.py derives the regex on the meta device for either base model instead of guessing.
- Config is strict-fail, and the nx3 profile/format pairing is enforced both ways: model_profile=nuextract3_qwen3 requires prompt_format=nuextract3 and vice versa (load_config L200-207); unknown YAML keys, packing=true, completion_only_loss=false, both 4bit+8bit, or truncate_policy=truncate_context are each a SystemExit. One JSONL row must remain one full example -- packing is banned.
- Loss is computed on the completion only, for BOTH prompt formats. CompletionOnlyCollator masks the prompt span to -100 and RuntimeErrors if the mask leaves zero label tokens for the whole batch (L516-517) or if a batch exceeds max_seq_length (L504-508).
- The seeded gen-eval subset selection is duplicated by design in two places and must stay in sync: train_lora.py's GenerativeEvalRetention (L950-954) and eval_checkpoints.py's _select_examples (L47-56) both use random.Random(seed).sample(range(n), n_eval) -- identical given the same seed/cap, so in-loop and offline-swept F1 for the same run are directly comparable. If one sampling rule changes without the other, cross-comparison silently breaks.
- sanitize_pred_units.py in THIS dir is a deliberate verbatim copy of lora_eval_cluster_bundle/sanitize_pred_units.py, kept so eval_checkpoints.py can apply the exact deployed dim-guard without a cross-repo dependency on the cluster node. - Per-parameter val F1 -- not loss or perplexity -- is the real dataset-quality / generalisation signal for BOTH eval paths. plot_gen_eval.py and audit_example_loss.py both flag loss/PPL over structured JSON a WEAK aggregate gauge (dominated by boilerplate/self-distilled tokens); its only informative use is the tail (highest-loss rows = likeliest mislabeled).
- eval_loss with dev == train is training loss under another name. train_lora warns at load (run(), L1265-1270); the deployed-recipe configs point dev_jsonl_path at a genuinely disjoint held-out val split so eval_loss is a real overfit signal that COMPLEMENTS (never replaces) the F1 selection signal.
- Never lower max_seq_length as an OOM fix. Range-shaped items concentrate in the longest (prosed-table) rows, so any length filter is a biased sample; if a length OOMs the answer is a bigger card, not a shorter window.
- Zero id_row overlap between any training JSONL and the hand gold, enforced upstream by finetune/trim_against_hand_gold.py. - Teaching descriptor/typed fields (drug_form, release_type, study_type, etc.) trades against scored numeric F1 in this recipe -- the descriptor_nx3 / audited-pool retrain scored 0.797-0.800 vs the winner's 0.834, a capacity trade proven real (not a train/eval prompt-drift artifact, ruled out separately) across two independent re-gens. ## S8 · Evaluate — LoRA adapter → generate on hand gold → all-parameter F1 + arm comparison

> Judge a fine-tuned LoRA adapter against the real hand gold: generate, marshal, score every PK parameter.

**Repo:** `lora_eval`  ·  **Source dir:** `lora_eval_cluster_bundle/`  

**God node:** `score_all_params_v2.py` — The one governed all-parameter scorer every arm routes through; it defines the headline metric (routed vs compound-aware), and score_by_dbsource + the dashboard import its functions to stay bit-identical to the headline.

The Evaluate stage judges a fine-tuned LoRA adapter (from S7) against the real 38-row hand gold, on the SAME prompt machinery training used so the number reflects the model, not prompt drift. `build_eval_prompts.py` (arm A) and `build_eval_prompts_armb.py` (arm B, slice-shaped) reconstruct the training prompt via `convert_synthgen_to_nuextract.build_compound_prompt` → `prompts.build_nuextract_prompt`. `run_eval_generation.py` loads NuExtract-2.0-8B in 4-bit, optionally applies the adapter, and greedy-decodes one completion per prompt on GPU — run once with `--adapter` (the fine-tuned arm) and once without (the stock baseline), so any delta is the adapter, not sampling. `merge_armb_predictions.py` unions arm B's three per-ADME-slice predictions back into one object per compound (mandatory: the scorer keeps one object per compound, so skipping the merge silently caps recall near a third), and `preds_to_armdir.py` marshals completions into `allparam_arms/<arm>/extract_<row_id>_*.json`. `score_all_params_v2.py` — the governed trio-v2 scorer and this stage's god node — then scores every PK parameter: each PKV is one comparable interval, item↔item matched within a tolerance, with a `--compound-aware` mode keying bags by (compound,param) versus the default row×param 'routed' mode (a different metric definition, never mixed). `split_gold_by_verdict.py` carves the gold into table- vs narrative-derived subsets and `score_by_dbsource.py` buckets by db_source — both reuse the scorer's own functions so the numbers match the headline. `soup_checkpoints.py` averages plateau checkpoints into one adapter, `build_oracle_manifest.py` builds the arm-E count-priming FLOOR manifest, and `verbatim_field_grounding.py` first-passes text-field grounding. **Invariants / honesty rules**
- --exclude-rows 2501: row 2501 is in BOTH the training corpus AND the eval gold (a 1-row leak) — always excluded from a scored eval.
- compound-aware vs routed (row×param) is a DIFFERENT metric definition, not a knob to average — the two full-gold lenses are separate comparable groups.

- On a filtered-gold subset (category / db_source) precision is confounded — read RECALL.

**Invariants / honesty rules**
- RELIABILITY GATE (resolver_tier): compound_identity rows with resolver_tier>=3 are fuzzy substring false positives (Kaftrio TEZ->bortezomib, IVA->bivalirudin) and are DROPPED to honest-NULL. Enforced twice: enrich_identity.py REJECT_TIER_GE=3 (L40, L192-195) and db.py DbResolver.resolve_identity max_resolver_tier=2 (config id_resolution.max_resolver_tier=2; SQL at L124-126 row-exact and L140 name-fallback).
- METABOLITE-NO-INHERIT (v83 H2): a metabolite gets its OWN identity from compound_identity matched per (row_id, compound_name); it NEVER inherits the parent drug's cid/unii. enrich_identity.py L187-216; step3 L464-469 also nulls a parent link on a row whose role is itself parent (N6 guard).
- HONEST-NULL, never fabricate: every DB helper returns None/[] on failure and downstream emits NULL + a *_source/identity_source/confidence note rather than a guessed id (db.py module docstring; step3 id_source='unresolved').
- identity is a metadata plane attached DOWNSTREAM, not extracted: build_silver_merged.py leaves compound.identity={} on purpose (L137); enrichment is a separate re-runnable post-processor.
- OVERRIDES ARE AUTHORITATIVE and durable: maps/identity_overrides.csv (or raw_llm_txt.identity_overrides DB mirror) and compound_aliases id columns WIN per-field over DB-resolved values; the pipeline never writes maps/, so they survive every rebuild.
- STEREO-SAFE dedup: dedup_key and _consolidate_by_shared_identity merge on full InChIKey / CID / UNII (stereo-specific) BEFORE the connectivity-only inchikey_skeleton, so enantiomers (citalopram/escitalopram, amlodipine/levamlodipine) are never merged (step3 L72-84, L162-209).
- DETERMINISTIC merges: PubChem UNII-section pick and cid->UNII load ORDER BY cid,value so a CID with >1 UNII resolves reproducibly across runs (step3 L227-230).
- ORPHAN parking: an event-compound absent from the parsed roster is NOT merged as a tracked compound; it goes to orphan_ddi_compounds with needs_id_inference=true (build_silver_merged.py L142-150).
- STRICT label_ready: ML labels require numeric normalized/effect values plus compound features; a censored bound (threshold_op gt/lt) blocks label_ready so a >99 can't ship as an exact point (step10 L295-299).
- next_action is REPORTER-ONLY (LOCKED v99 vocab RESOLVE_IDENTITY/CONFIRM_UNIT); it never changes label_ready/missing_reason/any value (step10 L161-198).
- RELIABILITY guards fail LOUD before mutating: assert_db_reachable refuses a DB-dependent run when MariaDB is down (avoids silent 141/0-xref builds unless --offline), assert_work_fresh refuses a partial run against a work/ cache built from a different input_json sha, assert_scope fails on out/ row-count collapse/>20% drift vs scope_manifest.json (common.py L549-683).
